## 1. Goal and boundaries

Complete this integrated flow:

**Ask a checked price question -> export and re-import a list -> reopen a saved
list offline with a visible age -> switch all three UI languages and confirm
contrast, personal-data controls, and history views.**

The app remains one local Spring Boot process with Thymeleaf forms, plain
HTML/CSS/JavaScript, Spring Data JPA, and an H2 file database. It has no
accounts, cloud storage, live list sync, background notifications, or offline
editing.

- The app searches and calculates from accepted records before any fact is sent
  to an AI model. AI may explain checked facts; it must never invent a price,
  retailer, stock state, date, purchase, or future claim.
- A wishlist entry, tracking choice, list item, reminder, and purchase remain
  different records. No action silently creates another.
- Missing prices stay unknown. A missing listing does not prove out of stock.
- R16, R19, R35, and R44 keep their conditional or future status. This milestone
  does not add buy/wait prediction, voice input, a response-time promise, or
  change-since-last-week comparisons.
- List sharing is a separate copy. Later edits do not sync.
- Offline use is read-only. Live refresh and remote chat are unavailable.
- R10/R14 remain tracked-only and conditional on dated records. History views
  show real dates and gaps; they do not invent a 30/90-day series.

## 2. Decisions D08–D13

| ID | Decision | Rule |
|---|---|---|
| D08 | AI provider and configuration | Use DeepSeek V4 Flash provided by CityU. Read the base URL, model name, and API key from server-side configuration only (`pricewatch.ai.base-url`, `pricewatch.ai.model`, `pricewatch.ai.api-key`). The key comes from the `PRICEWATCH_AI_API_KEY` environment variable or a local, untracked properties file. Never hardcode or commit the key. Never read the key from `opencode.json`. Do not print the key in logs, test output, or documentation. Assume an OpenAI-compatible chat-completions request until CityU supplies a different contract. Keep the client behind an interface. |
| D09 | Chat grounding | Product retrieval and price calculations are deterministic and run before the model call. If zero products match, explain that no checked record matches. If several match, ask the shopper to choose. With one exact product, build a checked-facts object and send only that object plus the question. Render the checked fact table on the page regardless of the model result. Every currency amount in the model answer must match a checked fact; otherwise discard the answer and show a deterministic fallback. A model failure or timeout leaves search, comparison, and the checked facts usable. |
| D10 | List sharing | Export a chosen list as a versioned JSON file. Import creates a new separate list; it never merges into an existing list. Validate the whole file before writing. A malformed, oversized, unknown-product, duplicate-product, or out-of-range input leaves every existing list unchanged. Product codes must exist in the accepting app's accepted catalogue; document that both local apps need a compatible catalogue. Preserve product, quantity, checked state, and the saved retailer choice. A saved retailer may keep its choice when its price is currently unknown; a retailer that is not listed for the product is rejected. |
| D11 | Offline saved list | Generate a self-contained read-only HTML snapshot for a chosen list. It contains inline CSS only, no scripts, forms, refresh controls, chat, or live URLs. It shows the saved amounts and a visible saved-on/data-age label, and states that the source price date is unknown. The snapshot is opened from the viewing device with the app stopped or the device disconnected. A service-worker cache is an alternative only if the team records why the file snapshot is unsuitable. |
| D12 | Languages and preferences | Use English, Traditional Chinese, and Simplified Chinese. App text comes from reviewed message bundles; product and offer labels use the source language values with the existing English -> Traditional -> Simplified fallback. Locale and contrast preferences are stored locally for the one local user and must work through normal forms without JavaScript. Machine translation output is not acceptance evidence. |
| D13 | Personal data and history | View, export, and delete the local user's personal records: lists, wishlist, tracking periods and observations, alerts, budget, reminders, and preferences. The accepted catalogue and its source metadata are source data, not personal records; they remain unless the team later adds a separate full-reset action. A list-sharing export includes only the chosen list. Deleting local data cannot remove copies already sent to another person. History views show only tracked products' available observations within the 90-day retention period, with explicit gaps and an empty state. |

## 3. Product-wide tracking

The shopper-facing control is per product, not per retailer.

- The default action is **Track this product** or **Stop tracking** for the exact
  product. Existing per-retailer periods remain internal history records so a
  drop comparison still uses one product/retailer series.
- Product-wide tracking covers current and future retailer listings. An accepted
  LIVE import enrolls a new retailer for a product-wide track.
- A product target applies to every active retailer period for that product. A
  drop rule remains per retailer because its evidence is per retailer.
- A reminder uses the product and quantity. Its optional retailer preference is
  a list choice, not proof of tracking. If a pinned retailer has no current
  price, the reminder explains the block, keeps the choice, and offers a listed
  retailer with a current price. It must not leave an enabled add action that
  cannot succeed.
- Existing per-retailer history and upgrade compatibility are preserved.

The implementation should reuse `ProductEntity.trackAllRetailers` and the
existing tracking periods where practical. A new table needs a recorded reason,
a migration path, and an old-to-new database check.

## 4. Shared contracts

### 4.1 Web routes

| Request | Purpose |
|---|---|
| `GET /ask` | Ask page and checked-facts display |
| `POST /ask` | Submit a question; may return a product chooser |
| `GET /list/export` | Download the current list as versioned JSON |
| `GET /list/import` | Import form and preview |
| `POST /list/import` | Validate and create a separate list |
| `GET /list/offline` | Download the read-only HTML snapshot |
| `GET /preferences` | Language and contrast preferences |
| `POST /preferences` | Save language and contrast choices |
| `GET /privacy` | Personal-data counts and controls |
| `GET /privacy/export` | Download personal records as versioned JSON |
| `POST /privacy/delete` | Delete personal records after confirmation |
| `GET /history/{code}` | Tracked product history with dates and gaps |

Existing routes keep their behaviour. Import and privacy writes are same-origin
POST forms covered by `LocalRequestGuard`.

### 4.2 Chat facts

The checked-facts object must contain at least:

- product code and displayed name/pack;
- each listed retailer and its decimal price or explicit unknown;
- lowest price and ties;
- the accepted import retrieval time and the unknown source-date statement;
- the question text.

No unaccepted catalogue, sample-as-live, or invented value may enter this object.
The model request contains no local file paths, API keys, or unrelated personal
records.

### 4.3 Transfer file

```json
{
  "format": "pricewatch-list",
  "version": 1,
  "exportedAt": "2026-11-18T00:00:00Z",
  "name": "My list",
  "items": [
    {
      "productCode": "173520",
      "quantity": 2,
      "checked": false,
      "retailerCode": "JASONS"
    }
  ]
}
```

- Reject an unknown `format` or `version`.
- Reject an empty item list, more than 999 items, non-integer quantities outside
  1–999, duplicate product codes, unknown product codes, inactive products, and
  retailer codes not listed for that product.
- Validate before creating the list. Do not partially write on failure.
- Treat imported text as data. Do not execute or render it as HTML.

### 4.4 Offline snapshot

- One self-contained `.html` file per chosen list.
- Contains product name, brand, code, quantity, checked state, saved retailer,
  saved unit and line amounts (or an explicit unknown), and the saved-on time.
- Contains no `<script>`, `<form>`, remote URL, live refresh, or chat control.
- States that prices are saved values, the source price date is unknown, and the
  copy is read-only.

### 4.5 Languages

- Use Spring `MessageSource` bundles for app text and validation messages.
- Use the same message keys from screen and controller code.
- Keep source product labels in their own `lang` attributes.
- Locale and contrast preferences persist for the local user and are applied on
  every page.
- Layout checks cover longer Chinese text at 375, 768, 1024, and 1440 px.

## 7. Completion checks for issue #21

Combine the per-workstream checks with one integrated run:

1. Ask a price question and receive an answer whose product, retailer, and
   amounts match checked records.
2. Ask an ambiguous question and receive a product chooser instead of a guess.
3. Make the AI client fail and confirm search, comparison, and checked facts
   still work.
4. Export a list, import it on a second local copy, and confirm the new list is
   separate with the same products, quantities, checked state, and retailer
   choices.
5. Submit a malformed transfer file and confirm no existing list changes.
6. Open the offline snapshot with the app stopped and confirm the saved amounts
   and age, with no refresh or chat.
7. Switch all three UI languages and confirm app text and product labels.
8. Confirm high contrast, keyboard focus, and non-colour status meaning.
9. Export and delete personal data; confirm the catalogue remains and a shared
   list export contains only that list.
10. Open a tracked product's history and confirm real dates, gaps, and an empty
    state.

Background cloud/device notifications, offline editing, live sharing, price
prediction, and full R16/R19/R35/R44 work remain outside this milestone.
