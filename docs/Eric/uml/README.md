# UML for the J01-J04 baseline

All PlantUML. Each has a `.puml` source and rendered `.svg` / `.png` beside it.
The sequence flow is split one diagram per job group.

| File | Covers |
|---|---|
| `baseline-j01-j04-usecase.puml` | What the shopper does: import, search, compare, add, view list, tick off |
| `baseline-j01-j04-class.puml` | Domain types and the J01/J02/J03/J04 rules attached to them |
| `baseline-j01-j04-architecture.puml` | All layers: UI templates/JS, `PageController` + view records, `CatalogueImporter`, stores/repositories, domain, H2 |
| `baseline-j01-j02-sequence.puml` | J01/J02 import, validation, and failure branch |
| `baseline-j03-sequence.puml` | J03 search and comparison, including missing prices |
| `baseline-j04-sequence.puml` | J04 add/edit list, restart, and reload |
| `baseline-j01-j04-er.puml` | The physical H2 schema as generated by Hibernate |

What the implementation record says they must show is checked against
[`../implementation-baseline-j01-j04.md`](../implementation-baseline-j01-j04.md).

## Regenerate

```powershell
java -jar plantuml.jar -tsvg -tpng baseline-j01-j04-class.puml
java -jar plantuml.jar -tsvg baseline-j01-j04-architecture.puml
java -jar plantuml.jar -tsvg baseline-j01-j02-sequence.puml
java -jar plantuml.jar -tsvg -tpng baseline-j03-sequence.puml
java -jar plantuml.jar -tsvg -tpng baseline-j04-sequence.puml
java -jar plantuml.jar -tsvg -tpng baseline-j01-j04-usecase.puml
java -jar plantuml.jar -tsvg -tpng baseline-j01-j04-er.puml
```

Any PlantUML 1.2024+ release works; the diagrams use only standard syntax (`alt`, `else`, `loop`,
`autonumber`, `note`). No project build step depends on the jar.

## ER diagram source

The ER diagram is drawn from the schema Hibernate actually created, not from the class diagram.
To re-check it after a mapping change, import the sample so the tables exist, stop the app, then
read `INFORMATION_SCHEMA` from the file database:

```
jdbc:h2:file:./data/pricewatch   user sa   (no password)
```

Tables: `CATALOGUE`, `PRODUCT`, `LISTING`, `SHOPPING_LIST`, `LIST_ITEM`.
Foreign keys: `PRODUCT.CATALOGUE_ID -> CATALOGUE.ID`, `LISTING.PRODUCT_CODE -> PRODUCT.CODE`,
`LIST_ITEM.LIST_ID -> SHOPPING_LIST.ID`. There is deliberately no FK from `LIST_ITEM.PRODUCT_CODE`
to `PRODUCT.CODE`, so a saved list keeps its rows when a newer catalogue drops a product.
